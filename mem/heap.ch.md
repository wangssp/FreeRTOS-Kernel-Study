# FreeRTOS 动态内存管理阅读笔记——heap_1 至 heap_5

## 代码阅读顺序

1. `heap_1.c`：先理解最简单的顺序分配。
2. `heap_2.c`：加入释放和空闲链表，但不合并相邻块。
3. `heap_4.c`：重点精读，理解分割、释放和相邻块合并。
4. `heap_5.c`：在 `heap_4` 基础上理解多个不连续内存区域。
5. `heap_3.c`：最后看对标准库 `malloc/free` 的简单包装。

源码：[heap_1.c](Z:/FreeRTOS-Kernel/mem/heap_1.c)、[heap_2.c](Z:/FreeRTOS-Kernel/mem/heap_2.c)、[heap_3.c](Z:/FreeRTOS-Kernel/mem/heap_3.c)、[heap_4.c](Z:/FreeRTOS-Kernel/mem/heap_4.c)、[heap_5.c](Z:/FreeRTOS-Kernel/mem/heap_5.c)。

工程只能选择并编译其中一种实现，因为它们都提供相同的 `pvPortMalloc()` 和 `vPortFree()`。

## 一、五种实现的区别

| 文件 | 内存来源 | 支持释放 | 合并相邻空闲块 | 适用情况 |
|---|---|---:|---:|---|
| `heap_1.c` | 内核静态数组 | 否 | 否 | 只在启动阶段创建对象，之后永不删除 |
| `heap_2.c` | 内核静态数组 | 是 | 否 | 旧方案，容易产生碎片 |
| `heap_3.c` | C 库堆 | 是 | 由 C 库决定 | 希望直接使用系统分配器 |
| `heap_4.c` | 一块连续内存 | 是 | 是 | 常用的通用选择 |
| `heap_5.c` | 多块不连续内存 | 是 | 同一区域内合并 | RAM 分散在多个地址区间 |

## 二、heap_1：只分配不回收

`heap_1` 只有一个“下一个空闲字节”的偏移：

1. 将申请大小按端口对齐要求向上取整。
2. 判断剩余空间是否足够。
3. 返回当前位置并推进偏移。

`vPortFree()` 不回收空间。它实现最小、行为最确定，也完全没有外部碎片。

## 三、heap_2：空闲链表

`heap_2` 把空闲块按大小排序，分配时寻找第一个足够大的块，必要时切分剩余部分。

释放后的块重新插入空闲链表，但不会与地址相邻的空闲块合并。运行时间较长且申请尺寸多变时，可能剩下许多无法利用的小块。

## 四、heap_4：重点主线

每个内存块前都有一个 `BlockLink_t`：

- `pxNextFreeBlock`：空闲时指向下一空闲块。
- `xBlockSize`：包含块头在内的块大小；最高位还用作“已分配”标志。

### 分配

`pvPortMalloc()` 的流程：

1. 首次调用时初始化堆和首尾哨兵。
2. 给用户大小加上块头，并按字节对齐。
3. 在按地址排列的空闲链表中寻找第一个足够大的块。
4. 若剩余空间足以形成有效块，则切分。
5. 从空闲链表移除已分配块，设置分配标志并更新统计量。
6. 返回块头之后的用户区域。

### 释放

`vPortFree()` 根据用户地址找到前面的块头，清除分配标志，再调用 `prvInsertBlockIntoFreeList()`。

插入时检查前后地址是否连续：

- 与前块连续则向前合并。
- 与后块连续则向后合并。

因此 `heap_4` 能减少外部碎片，但不能保证任意申请一定成功：总空闲空间足够时，也可能没有足够大的连续块。

## 五、heap_5：多个内存区域

`heap_5` 的分配与合并逻辑基本等同于 `heap_4`，区别是内存来自用户提供的多个 `HeapRegion_t`。

使用前必须调用 `vPortDefineHeapRegions()`：

- 区域按地址升序排列。
- 每个区域提供起始地址和长度。
- 数组最后用 `{ NULL, 0 }` 结束。
- 区域不能重叠。

不同物理区域之间不会合并，即使它们在空闲链表中相邻。

## 六、共同规则

- 所有申请大小都按 `portBYTE_ALIGNMENT` 对齐。
- 任务、队列、定时器等动态创建最终都依赖 `pvPortMalloc()`。
- 分配失败时可启用 `vApplicationMallocFailedHook()`。
- `xPortGetFreeHeapSize()` 只表示总空闲量；`xPortGetMinimumEverFreeHeapSize()` 更适合观察历史峰值占用。
- `vPortGetHeapStats()` 可进一步查看最大空闲块和空闲块数量。
- 不能在 ISR 中调用动态内存分配接口。

## 七、值得记录的设计

- 多个实现保持同一接口，使应用无需知道具体分配算法。
- `BlockLink_t` 放在用户区之前，释放时可由用户指针直接找到元数据。
- `heap_4` 的空闲链表按地址排列，使相邻块合并只需检查前后节点。
- 块大小的最高位复用为分配标志，避免额外状态字段。
